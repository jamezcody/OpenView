# Unified search and map controls

The side pane now contains **Map view**, one **Overlays** list, a complete **Map legend**, and expandable source/update/filter settings. Space/Layers/Land/Traffic tabs and the duplicate address/parcel switches have been removed. Existing 3D navigation, basemaps, orbital timeline, property inquiry, source browsers, radio filters, and live-traffic settings remain available.

Type in **Search everything** to search map records. Press Enter or the arrow button to request online place/address results. Arrow keys select a result, Enter opens it, and Escape closes search. Click or tap any result to navigate and enable its layer. Radio searches reset radio filters so the chosen record is visible. Station and traffic positions are resolved from their data at selection time; satellite search never navigates to the catalog's placeholder coordinates.

Same-name records with distinct source identities remain separate. Coordinates and source identifiers distinguish radio/park matches. Local matches use accent-insensitive, case-insensitive matching of every word; exact names/IDs rank first. Results are bounded to 60 initially, with more available to 500 before requiring a narrower query. Provider-ranked place results precede local results after online submission. Ten existing map shortcuts also remain searchable.

## Data access and refresh

No prepared search files are requested on initial page load. First search use fetches `public/search/latest.json`, two versioned navigation indexes and the small FCC manifest. The radio tuple/dictionary file is **10,431,180 bytes**; park metadata is **2,692,547 bytes**. Gzip measurements are **3,994,964** and **291,825 bytes** respectively, not guaranteed transport sizes. These contain navigation metadata, no nationwide boundary geometry. Files are bounded and SHA-256 verified before indexing. Results stay in memory for the current page; turning map overlays off does not remove their search catalog. Refresh search catalogs is in Search coverage & report updates.

Full radio records and park vector tiles remain on demand. Search stores exact record locators and release identifiers. A source-release mismatch produces an explicit message instead of opening the wrong record. Updating radio or park assets requires rebuilding search indexes from matching releases. The raw inputs and offline preparation tooling are intentionally not included in the public production source; an operator must independently preserve provenance, source licences, geometry checks, and immutable release identifiers when replacing prepared data.

The server's `/api/search` queries the [Photon API](https://github.com/komoot/photon/blob/master/docs/api-v1.md) at `https://photon.komoot.io/api`. The [public demo policy](https://github.com/komoot/photon#demo-server) permits reasonable use, may throttle extensive use, and provides no availability guarantee. No credentials or paid service are required. `PHOTON_API_URL` can select an operator-configured HTTPS Photon endpoint without changing client code. There is no automatic online autocomplete: submitted queries are bounded to 3–180 characters, requests time out after 18 seconds, responses are capped at 1 MiB, identical requests coalesce, and successful results cache for 24 hours in the existing bounded provider cache. A per-isolate concurrency/one-second gate reduces bursts; this is not a global multi-user rate limiter. No current map-center bias is sent. Online failures preserve local results. OSM attribution and [ODbL terms](https://www.openstreetmap.org/copyright) are accessible in search and address details.

## Verification

The unified-search regressions cover coordinate parsing, accent/ID search, deduplication, source scope, Photon schema/address provenance, provider caching/coalescing, response bounds, checksums, release matching, and representative park/radio searches. TypeScript and production compilation are checked with the standard app commands.

## Camping search

Camping is queried independently through a bounded static prefix index, including all 274,534 source records while its layers are off. Names, state codes, kinds, source names and explicit parent names are indexed. Full source identities such as `ridb_campsite:1` and `osm:node/571276260` resolve through hashed detail shards. Nullable camping coordinates never become a search marker or camera destination. Search targets carry both source ID and immutable release, so details and parent links cannot silently resolve to a different snapshot. Up to 40 results are displayed within request/byte limits with total counts and narrowing guidance. See [CAMPING.md](./CAMPING.md).
